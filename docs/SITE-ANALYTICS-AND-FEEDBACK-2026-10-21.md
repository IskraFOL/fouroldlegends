# КТ 21.10.2026 — аналитика посещений и исправление формы сайта

Публичный адрес: https://iskrafol.github.io/fouroldlegends/

## Проверенные изменения

### Обратная связь (рабочая функциональность)

- FormSubmit используется через официальный AJAX API, без лишнего открытия вкладки при штатной отправке.
- Сообщение «принято» появляется только при HTTP-успехе и JSON success=true (или строковом "true").
- Сервис подтвердил приём запроса — это НЕ гарантия, что письмо прошло спам-фильтры адресата.
- При ошибке или недоступности сервиса текст остаётся на месте, автоматических повторов нет.
- Пользователь может вручную открыть прежнюю резервную форму FormSubmit в новой вкладке.
- Повторные нажатия во время запроса блокируются; статусы доступны скринридерам (role=status, aria-live=polite).
- Для русского и английского языков тексты различаются.
- Без JavaScript сохранено исходное поведение HTML-формы.
- Получатель, темы сообщений и остальные поля формы не изменены.

### Аналитика посещений (требует разовой активации)

- Подключён загрузчик Cloudflare Web Analytics, совместимый с GitHub Pages.
- В публичном файле assets/fol-site-analytics.js Site Token пока ПУСТОЙ.
- Пока нет Site Token, НЕ загружается beacon, НЕ отправляются события и НЕ появляются цифры.
- Cloudflare не требует смены домена, DNS или переноса с GitHub Pages.
- Это счётчик посещений (visits) и просмотров страниц (pageviews), а НЕ достоверный учёт всех уникальных людей.
- Данные появляются только с момента активации; исторические посещения задним числом не восстановить.
- Хеш-навигация (#) не учитывается как отдельная страница.
- Статистика приватна в панели Cloudflare, не выводится публично на сайте.

**Действия владельца для активации (понадобится 1 раз):**

1. Открыть https://dash.cloudflare.com/ и войти/создать бесплатный аккаунт.
2. Analytics & Logs → Web Analytics → Add site.
3. Ввести hostname: iskrafol.github.io (НЕ полный URL с /fouroldlegends/).
4. Скопировать *Site Token* Web Analytics (обычно 32 hex-символа). НЕ отправлять API Token, пароль или ключ аккаунта.
5. В assets/fol-site-analytics.js заменить пустую строку siteToken = '' на этот публичный Site Token.
6. После публикации открыть сайт и проверить загрузку https://static.cloudflareinsights.com/beacon.min.js в DevTools Network.
7. Через несколько минут проверить метрики в панели Cloudflare.

Официальная инструкция: https://developers.cloudflare.com/web-analytics/get-started/

## Проверки до слияния

6 сценариев на моделируемом DOM без реальной отправки писем:
1. Ответ FormSubmit success=true → корректный URL/POST, сброс формы, статус успеха.
2. Ответ success=false → ошибка, текст сохранён, резервный переход только по нажатию.
3. Исключение сети → статус ошибки, без сброса текста.
4. Двойная отправка → ровно один POST, кнопка разблокируется после завершения.
5. Другие формы → их обработка не перехватывается.
6. Cloudflare без токена → нет запросов; тестовый токен → создан единственный beacon-скрипт.

Проверка синтаксиса обоих JS-файлов: PASS.

**Не выполнялось:** отправка реального письма через FormSubmit (чтобы не создавать тестовые сообщения на рабочем адресе), статистика в панели Cloudflare (пока нет Site Token), реальное браузерное тестирование двух языков и мобильной вёрстки. Это не следует выдавать за PASS.

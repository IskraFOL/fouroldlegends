# КТ 21.10.2026 — аналитика посещений и исправление формы сайта

Публичный адрес: https://iskrafol.github.io/fouroldlegends/

## Проверенные изменения

### Обратная связь (рабочая функциональность)

- FormSubmit используется через официальный AJAX API, без лишнего открытия вкладки при штатной отправке.
- Сообщение «принято» появляется только при HTTP-успехе и JSON success=true (или строковом "true").
- Сервис подтвердил приём запроса — это НЕ гарантия, что письмо прошло спам-фильтры адресата.
- При ошибке или недоступности сервиса текст остаётся на месте, автоматических повторов нет.
- Пользователь может вручную открыть прежнюю резервную форму FormSubmit в новой вкладке.
- Повторные нажатия во время запроса блокируются; статусы доступны скринридерам (role=status, aria-live=polite).
- Для русского и английского языков тексты различаются.
- Без JavaScript сохранено исходное поведение HTML-формы.
- Получатель, темы сообщений и остальные поля формы не изменены.

### Аналитика посещений — АКТИВИРОВАНА 21.10.2026

- В `index.html` встроен **официальный Cloudflare Web Analytics beacon** в формате, полученном владельцем: `<script type="module" src="https://static.cloudflareinsights.com/beacon.min.js" data-cf-beacon='...'></script>`.
- В `data-cf-beacon` используется публичный **Site Token веб-аналитики**, не приватный API-токен.
- Старый вспомогательный скрипт `assets/fol-site-analytics.js` удалён: он больше не нужен и не должен загружать beacon второй раз.
- GitHub Pages, домен/DNS, React, фотографии, Tracker, скачивания и форма обратной связи на этапе активации не менялись.
- В панели Cloudflare могут отображаться визиты (visits), просмотры страниц (pageviews) и источники трафика. Это не точное число всех уникальных людей: часть измерений может блокироваться настройками браузера.
- Статистика доступна владельцу в панели Cloudflare, публичного числового счётчика на сайте нет.
- Исторические посещения до активации восстановить нельзя.
- **Активация кода не равна подтверждению первых измерений в Cloudflare**: нужно проверить данные в панели.

**Проверка после публикации:**

1. Открыть https://iskrafol.github.io/fouroldlegends/ .
2. В HTML проверить одно включение `beacon.min.js` и правильный публичный `data-cf-beacon`.
3. В DevTools → Network проверить загрузку `static.cloudflareinsights.com/beacon.min.js` без ошибок.
4. Открыть https://dash.cloudflare.com/ → Analytics & Logs → Web Analytics, выбрать сайт `iskrafol.github.io` и через некоторое время проверить появление visits/pageviews.

## Проверки до слияния

6 сценариев на моделируемом DOM без реальной отправки писем:
1. Ответ FormSubmit success=true → корректный URL/POST, сброс формы, статус успеха.
2. Ответ success=false → ошибка, текст сохранён, резервный переход только по нажатию.
3. Исключение сети → статус ошибки, без сброса текста.
4. Двойная отправка → ровно один POST, кнопка разблокируется после завершения.
5. Другие формы → их обработка не перехватывается.
6. На подготовительном этапе Cloudflare без токена → нет запросов; тестовый токен → создан единственный beacon-скрипт. При активации установлен официальный HTML-тег вместо загрузчика.

Проверка синтаксиса обоих JS-файлов: PASS.

**Не выполнялось:** отправка реального письма через FormSubmit (чтобы не создавать тестовые сообщения на рабочем адресе), реальные цифры в панели Cloudflare (после активации ещё не подтверждены), реальное браузерное тестирование двух языков и мобильной вёрстки. Это не следует выдавать за PASS.

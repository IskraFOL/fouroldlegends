# КТ 21.10.2026 — исправление открытия CAPTCHA / новой вкладки при отправке обратной связи

## Сообщение пользователя и воспроизведение

После первого обновления формы пользователь прислал скриншот: при отправке с сайта всё ещё открывалась новая вкладка FormSubmit с Google reCAPTCHA «Almost There». Это **дефект UX**; он не доказывает доставку письма.

Повторный аудит **публичного React-бандла** `assets/index-photos-20261020.js` выявил, что несмотря на отдельный AJAX-скрипт, исходный React-компонент всё ещё содержал:
- `<form action="https://formsubmit.co/…" method="POST" target="_blank">` — возможность нативного перехода в новую вкладку;
- обработчик `onSubmit`, который не вызывал `preventDefault()`;
- инструкции RU/EN «Отправка откроется в отдельной вкладке»;
- прежний AJAX-обработчик при ошибке **предлагал резервную FormSubmit HTML-отправку в новую вкладку**. Она закономерно могла показать reCAPTCHA.

Это означает, что прошлые тесты AJAX не проверяли все реальные пути отправки.

## Исправлено в ветке fix/feedback-stay-on-page-2026-10-21

1. В **публичной собранной React-версии** точечно удалён `target="_blank"` у формы и добавлен `onSubmit: event.preventDefault()` как защита на случай, если основной AJAX-обработчик не загрузится. Все остальные ссылки, фотографии, Tracker, игры и контент оставлены без изменения.
2. Старые RU/EN подсказки об отдельной вкладке заменены на точное описание отправки внутри сайта. При недоступном обработчике выводится честное сообщение об ошибке.
3. Новый `assets/fol-feedback-v2.js` отправляет данные официальным `https://formsubmit.co/ajax/...` методом POST, перехватывает исходную отправку на этапе capture и отменяет её **синхронно** до обращения к сети. Удаляется даже закэшированный старый атрибут `target`.
4. При ответе `success=true` выводится «FormSubmit принял сообщение», а не «письмо гарантированно доставлено». При ошибке формы текст остаётся; можно скопировать его прямо на сайте или по явному действию открыть почтовое приложение через `mailto:`. **Ни один из запасных способов не открывает FormSubmit CAPTCHA автоматически**.
5. Новый `assets/fol-feedback-v2.css` оформляет статус и копируемый текст для мобильного/десктопа. Старые `fol-feedback-ajax.js/css` оставлены как неиспользуемые файлы, чтобы сохранённые в кэше HTML-страницы не получали 404.
6. В `index.html` изменены ссылки на JS/CSS v2 и добавлен query revision к React-бандлу для обхода старого браузерного кэша.
7. На сайте **не отключена CAPTCHA** через `_captcha=false`, действующие механизмы FormSubmit по защите от спама и hidden honeypot сохранены. Не создавался сервер, не менялся адрес получателя/внешний хостинг.

## Проверка

- **12 статических проверок PASS:** полная синтаксическая проверка JS включая React-бандл; нет старых инструкций и нативного `target=_blank`; работающий `preventDefault` в React; JS v2 перехватывает submit; отсутствует резервный HTML POST; ссылка `mailto` и копирование; корректные имена файлов; Cloudflare Web Analytics на месте.
- **6 сценариев смоделированных DOM-событий PASS** (на свежем JS из GitHub, без реальной отправки письма):
  1. FormSubmit JSON success → единственный AJAX POST, форма сброшена, никакого перехода даже с устаревшим атрибутом `target=_blank`.
  2. `success=false` → видимая ошибка на текущей странице, текст не очищен, возможность копирования и почты, автоматической навигации нет.
  3. Сбой сети → ошибка на странице, текст сохранён.
  4. Двойное нажатие → лишь один запрос.
  5. Другие формы не перехватываются.
  6. Если AJAX-обработчик отсутствует → исходный React `onSubmit` предотвращает переход, не пытается послать данные через HTML.

**Чего НЕ проверяли:** реальную доставку письма через FormSubmit и реакции внешнего CAPTCHA-сервиса в личном браузере; после публикации понадобится один тест от пользователя/владельца. Не выдавать симуляцию DOM за полное интеграционное тестирование.

## Инструкция после публикации

Открыть https://iskrafol.github.io/fouroldlegends/ и выполнить принудительное обновление `Ctrl+F5` (или открыть в приватном окне), поскольку старый браузер мог закэшировать React-бандл.

В разделе «Оставь свой след» не должно быть текста «откроется в новой вкладке». При отправке на той же странице появляется «Отправляем», затем подтверждение или честная ошибка. Страница FormSubmit «Almost There» не должна открываться автоматически.

Если FormSubmit откажет (спам-защита, сервер или сеть), это отобразится как неуспех без навигации; тогда нужно проверить причину отдельно, а не отключать CAPTCHA наугад.
